# 参数与复核

已有命令继续适用。所有输入路径相对当前工作目录；输出存在时使用新版本名称。

| 参数 | 含义 |
|---|---|
| source | 连续帧目录，或明确布局的单张精灵表 |
| --output / -o | GIF文件路径，默认output.gif |
| --fps | 默认12，可用小数，范围0<fps<=100；用于没有指定durations时的均匀节奏 |
| --layout | 精灵表行数x列数，例如2x4；目录输入不使用此项 |
| --boundaries | 可选JSON文件，含x/y像素边界数组；不能穿过可见图案 |
| --size | 可选正方形输出边长，至少16；省略则保留输入画布尺寸 |
| --anchor | center或bottom，默认center；作用于整个序列的公共构图 |
| --alpha-cutoff | 透明阈值1..255，默认128；低于阈值的像素透明，其余不透明 |
| --sequence | 从1开始的帧编号列表，例如1,2,3,2,1；允许重复编号 |
| --durations | 逐播放帧毫秒列表，数量须与sequence展开后的播放帧数一致，覆盖均匀fps节奏 |
| --overlay | 可选静态PNG等图层，必须与最终画布尺寸相同，固定坐标叠加到每一帧 |
| --max-size | 本地最大体积，单位KiB，默认0表示不限制；不通过缩小尺寸达标 |
| --optimize | 额外尝试gifsicle -O3无损优化，仅接受验证通过且更小的结果 |

## 帧与时长

目录合并扫描PNG/JPG/JPEG/静态WebP，扩展名不区分大小写，按自然顺序排列：1、2、10。目录各帧画布尺寸必须一致；坏帧报错，不跳过。动画PNG/WebP等须先明确拆成连续帧。

精灵表按行优先读取，顺序从左到右、从上到下。透明图的切线以alpha>24识别可见内容；同仓库安装可寻找透明间隙，无可靠切线时停止。只有GIF Maker独立安装时，安全的等分切线仍可使用；需要非等分透明寻边时安装wechat-sticker-maker，或提供安全边界/独立帧。不透明精灵表按明确布局等分，内容是否跨格由用户和Agent复核。

边界JSON示例：

```json
{"x": [0, 444, 888, 1332, 1774], "y": [0, 452, 887]}
```

这是特定2x4源图的示例，不可照搬。非整除或自适应切片按名义网格原点恢复到公共画布，不对每个角色重新居中。--size进一步对所有播放帧可见范围取并集，用相同裁剪框与缩放比例处理，四周留约5%空白；bottom只改变整个并集在画布中的位置。相机漂移与错误生帧需上游修复。

帧时长以10ms粒度编码；显式durations每项为10..655350ms，按累计时间取整，避免每一帧截断导致总时长持续漂移。例如24帧、24fps会分配40/50ms，总计1000ms。短片段的总时长仍可能取整，实际值记录于报告。loop固定为0（永久循环）。重复画面可被编码器合并为更长停顿，源帧数与编码帧数不要求相等。

## 透明与固定文字

共享调色板保留最多255个可见颜色及一个专用透明索引；不透明像素即使颜色与透明槽接近，也不会被当成透明。透明阈值在最终构图之后应用，不改写原始RGBA输入；量化默认不加颜色抖动，避免动画中的颗粒跳动。

毛发或细笔画过薄时可降低阈值；杂色边缘仍需检查。GIF采用二值透明，保留完整柔和alpha应另用原始PNG帧等支持alpha的格式。阈值与调色板不能保证修复源图已混入的白边。

固定文字使用wechat-sticker-maker的排字能力或已有透明文案层，在上游完成字号、字体与位置选择；本脚本只复用等画布图层，不再实现字体系统。图层最后叠加，源画面需事先留出文案空间。输入帧已有文案时不提供overlay。

## 压缩与验收文件

达到--max-size目标时默认无需gifsicle。超限时尝试-O3，再依次尝试有限的lossy强度30/80/120/200；输入始终是原始编码结果，不累积多轮损耗。缺少gifsicle或所有尝试失败就停止，原始输入保持不变。

--optimize为已达标输出增加一次可选无损尝试，不保证更小；工具缺失或结果未通过校验时保留已达标版本，并在报告记录情况。无损优化比较解码像素与时间线；有损优化校验画布、透明、循环和时间线，颜色质量仍需视觉检查。

成功输出：

- action.gif：最终GIF。
- action.animation.json：输入顺序、切分边界、播放列表、实际时长、公共构图、透明阈值、压缩方式和本地检查结果。
- action.preview.png：从最终GIF解码生成；每个采样画面同时放在浅/深背景上，最多采样12个编码帧，采样编号写入报告。

预览是静态检查图，不代替实际播放。检查角色/文案的清晰度、首尾衔接、动作位移、透明边缘和残影。失真或动作不自然时修复相应源帧，不把提高fps或淡入淡出当作生成真实中间动作。

## 运行环境

run.sh优先使用满足Pillow>=10的技能.venv，其次使用满足依赖的当前python3。只有缺少可用环境时才按requirements.txt安装，不在每次启动升级pip；失败清理本次新建环境，已有环境保留。已有不完整venv且当前Python也不可用时，明确报错供修复。

也可在已经准备好的环境中直接执行python3 <skill-dir>/scripts/make_gif.py。gifsicle由系统包管理器安装，示例：macOS使用brew install gifsicle。平台尺寸和体积预设以实际提交页核对，不把950KiB或50KiB写成通用审核规则。
